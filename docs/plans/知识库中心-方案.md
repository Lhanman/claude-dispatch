# 知识库中心：实现方案

- 日期：2026-09-23
- 级别：L3（两个仓库、新增一整块能力）
- 需求来源：`docs/plans/知识库中心-需求交接.md`
- 决策方式：使用者授权「按推荐决策做，最后给决策链」，所以交接文档里的「待定问题」在本文件逐条定案，不再单独提问。

## 目标

把个人知识库（`kb_dir`，Obsidian 风格的 Markdown 笔记）里**白名单内、且通过敏感检查**的笔记，自动同步到公开文档站，和已有的 HTML 文档共用一个首页，支持搜索、标签筛选和知识图谱。公司内容一律不上站。

## 决策链

### D1 定案方式：方案写进 `docs/plans/`，不引入 OpenSpec

本仓库还没有 `openspec/`，只为这一个特性引入一套新目录和命令，收益不抵成本。方案、任务组、验收标准都写在本文件里。

### D2 公开范围：顶层目录白名单 + 单篇退出

- 新增配置 `kb_public=个人项目,技术笔记`（`~/.claude/dispatch/config`）。**没有配置就不同步**，不设默认值，避免误传。
- 只有白名单顶层目录下的笔记参与同步；`kb_exclude` 里的目录仍然排除。
- 单篇退出用 frontmatter `publish: false`（沿用 Obsidian Publish 的字段名）。
- **不提供「强制公开」**：白名单外的笔记没有任何办法上站。公司目录（`云相册`、`mimo`、`fly`、`每日工作计划`）因此在结构上就不可能被发布，而不是靠检查兜底。

### D3 `fly/` 不公开

`fly/源码依赖/*` 两篇命中 `DJI`、`mimo` 和本机绝对路径，是公司内容。不进白名单，敏感检查也会拦下。

### D4 敏感检查：原文过一遍，产物再过一遍，命中就整篇跳过

- 对**笔记原文**（含相对路径和标题）跑现有 `scan()`：本机路径、邮箱、疑似密钥、`pages_deny`。命中即整篇跳过，报告里列出篇名和命中的词。
- 渲染后的 HTML **再扫一次**，命中同样跳过。防止渲染过程（例如把 `[[链接]]` 展开成标题）带出新的敏感内容。
- `kb-sync` **不支持 `--allow`**，不能放行，也不做敏感词替换。
- 新增一条「提醒」级规则：`password/secret/token=<值>` 形式的赋值。不拦截（`个人项目/博客` 里都是 `your-secure-password`、`admin123` 这类占位或本地默认值），但在报告里显示，由使用者判断。

### D5 渲染位置：本地渲染成 HTML，Actions 只做复制

三种做法里选「本地渲染」：

| 方案 | 取舍 |
|---|---|
| 本地渲染成 HTML（**选中**） | 和现有「仓库存中文路径、Actions 按清单复制」的结构一致；Actions 零依赖；渲染逻辑在插件里，可单测；公共仓库里不出现未渲染的原始 md |
| 推 md，Actions 里 pip 装库渲染 | Actions 多一层依赖和构建时间；本地测试也要装库；公共仓库里存原文，`[[链接]]` 等要另做净化 |
| 推 md，浏览器端 marked.js 渲染 | 首屏闪烁、无 JS 不可读、依赖 CDN；好处只是省掉自己写渲染器 |

本机没有 `markdown`、`markdown_it` 任何一个库，插件的既有约定也是只用标准库，所以自带一个精简渲染器 `lib/markdown_lite.py`：标题（带锚点 id）、段落、`**粗体**`/`*斜体*`/`~~删除线~~`/`` `代码` ``、围栏代码块、引用、有序无序列表（含嵌套与任务列表）、GFM 表格、分割线、链接与图片、行内转义。原始 HTML 一律转义（笔记里的 `<div>` 按文本显示），不做白名单，避免脚本混进公开页面。

代码高亮不做：需要额外 CDN 依赖，收益低；用等宽字体加浅背景块即可。

### D6 `[[链接]]`、图片、附件

- `[[标题]]`、`[[标题|别名]]`、`[[标题#小节]]`、`![[嵌入]]` 都解析；代码块和行内代码里的不解析。
- 目标在**已发布集合**里 → 渲染成 `../<slug>/` 的链接，同时记一条图谱的边。
- 目标不在已发布集合（未公开、或根本不存在）→ 整体替换成纯文本「（未公开）」。**不保留别名**，因为别名也可能是未公开笔记的标题。
- 相对路径的 Markdown 链接（`[x](../某笔记.md)`）按同样规则处理。
- 本地图片和附件（`![](image.png)`、`![[图.png]]`）**不上传**：图片内容无法扫描，宁可不传。渲染成「（图片未公开：alt）」，并在同步报告里列出。`http(s)` 图片原样保留。

### D7 网址与 slug

- 笔记线上网址 `/kb/<slug>/`，HTML 文档仍是 `/p/<slug>/`，图谱在 `/graph/`。
- slug 取值顺序：frontmatter 的 `slug` → 上次同步时这条路径用过的 slug（存在 `kb.json`）→ 正文哈希相同的旧条目的 slug（**改名保持网址不变**）→ 由标题里的英文字母数字生成（≥4 个字符才用）→ `note-<正文哈希前 6 位>`。同名冲突时追加 `-2`、`-3`。
- `dispatch:note` 以后为新笔记写一个英文 `slug`，老笔记不动（不批量改使用者的笔记）。

### D8 老笔记缺 frontmatter：页面上兜底，不改原文

- `title`：frontmatter → 一级标题 → 文件名。
- `summary`：frontmatter → 正文第一段（截断到 80 字）。
- `project`：frontmatter → 二级目录名（`个人项目/博客/...` → `博客`）→ 顶层目录名。
- `type`：frontmatter → 空（页面上不显示类型标签）。
- `tags`：frontmatter → 空。
- 不批量补写 frontmatter：那是在改使用者的笔记，需要单独征得同意。

### D9 首页信息架构：文档和笔记共用一个首页

- 首页 = 知识库中心：统计（N 篇笔记 · M 篇文档 · 最近更新）、搜索框、类别筛选（全部 / 笔记 / 文档）、标签筛选、两种排布（按时间 / 按项目，服务端各渲染一份，JS 切换显隐）、知识图谱入口。
- 搜索走前端：每条目的 `data-text` 里放标题、摘要、标签、项目、类型、全部小节标题和正文前 600 字。不再单独做 `search.json`，公开笔记规模（几十篇）下首页体积可控。
- 深浅色跟随系统，移动端单列。

### D10 知识图谱：笔记节点 + 标签节点

- `graph.json` 数据内联在图谱页里（规模小，省一次请求）。
- 节点：每篇公开笔记（圆点，按项目着色，半径按度数）＋ 被 **2 篇以上**公开笔记共用的标签（菱形）。只被一篇用到的标签不成关系，不出节点。
- 边：笔记→笔记（`[[链接]]`，实线）、笔记—标签（虚线）。共同标签通过标签节点体现，避免 O(n²) 的笔记两两连线。
- 布局用 d3 v7（jsdelivr），SVG + 拖拽 + 缩放；点笔记节点跳转笔记页，点标签节点高亮它的邻居；搜索框高亮匹配节点；节点超过 40 个时标签文字按缩放层级显示。
- 无 JS 或 CDN 不可达时，页面里服务端渲染的「按标签分组列表」作为兜底（JS 初始化成功后隐藏）。
- 未公开的笔记和只出现在未公开笔记里的标签，不进入 `graph.json`。

### D11 同步命令：`dispatch-pages kb-sync`，每次全量

- 放在 `dispatch-pages` 里，复用它的配置、敏感检查、目录页生成和 git 提交推送；知识库侧的选取、渲染、页面模板放在 `lib/kbsite.py`。
- **每次全量同步**：算出应发布集合 → 写入或更新 → 删除 `知识库/` 下不在集合里的文件 → 重建 `kb.json`、首页、图谱页 → 一次提交推送。笔记改名、删除、改成 `publish: false`、命中敏感词，都靠下一次全量同步自动下线。
- `--dry-run` 只报告不写盘；`--no-push` 只提交不推送。
- `dispatch:note` 写完笔记后自动执行一次（使用者已授权自动发布）。

### D12 两个仓库的顺序

- 知识库仓库（私有）：只读，不做任何 git 操作（沿用 `dispatch:note` 的约定）。
- 文档站仓库（公开）：同步内容 → 提交 → 推送。推送失败返回退出码 4，本地提交保留；顺带修一个既有问题：本地没有新变化但落后于远端时，原来会直接返回、不补推，现在会补推一次。
- 插件仓库：代码改动不自动提交，交由使用者决定。

### D13 验证

`python3 -m unittest discover -s tests`，通过 `dispatch-verify` 执行。重点用例：

1. 白名单外目录（含伪造的公司目录）的笔记不出现在任何产物里；
2. 白名单内但正文命中敏感词的笔记整篇跳过，标题不出现在 `kb.json`、首页、图谱、任何笔记页里；
3. `publish: false` 跳过；
4. 公开笔记里指向未公开笔记的 `[[链接]]`，渲染成「（未公开）」，不泄露标题；
5. 共同标签产生标签节点和边，未公开笔记不进图谱；
6. 笔记页生成、`build-site.py` 产出 `kb/<slug>/index.html` 和 `graph/index.html`；
7. 删除笔记后再同步，站点文件随之下线；
8. 笔记改名（内容不变）后 slug 不变；
9. Markdown 渲染器的单测（表格、嵌套列表、代码块、转义、wikilink）；
10. 既有 7 个 `dispatch-pages` 测试继续通过。

## 任务组

1. **渲染器**：`lib/markdown_lite.py` + 单测。
2. **同步核心**：`lib/kbsite.py`（选取、模型、slug、wikilink 解析、图谱数据）+ `dispatch-pages kb-sync` + 单测。
3. **页面**：笔记页模板、首页改造（文档 + 笔记）、图谱页、`build-site.py` 更新 + 单测。
4. **接入**：`skills/note`、`skills/setup`、`router/KB.md`、`router/PAGES.md`、README、版本号。
5. **上线**：真实同步一次，人工核对站点。

每组做完按 `dispatch:code-review` 审一次。

- `bin/dispatch-pages`：新增 `kb-sync` 子命令，首页改为文档 + 笔记合流，部署脚本按 `kb.json` 生成 `kb/<slug>/` 和 `graph/`。
- 线上：首页 <https://lhanman.github.io/>、图谱 <https://lhanman.github.io/graph/>、笔记 `/kb/<slug>/`。

两轮独立审查各查出一批问题，均已修复并补了回归测试：

1. 普通 Markdown 链接的文字会经由标题锚点 id、目录和兜底摘要泄露未公开笔记的标题 → 这三处改为从渲染后的 HTML 取文本。
2. 渲染出空段落时整次同步崩溃（运算符优先级写错）。
3. 两篇笔记的文件名被 `safe_name` 归一到同一路径时互相覆盖 → 仓库路径去重。
4. 新笔记会抢走老笔记已经公开的 slug → 分配顺序改为「已有网址的先保号」。
5. 带 BOM 或前置空行的 frontmatter 解析不到，`publish: false` 被静默忽略。
6. 图谱数据内联进 `<script>` 时没转义 `<`，标题里带 `</script>` 可以闭合脚本块。
7. 第二遍检查踢掉某篇后不重算摘要，被拦下的标题会留在别人的摘要里；重渲染循环也改成收敛到稳定为止。
8. 没有 `kb.json` 时 `rebuild` 会造一个空图谱页。
9. 以 `/` 结尾的相对链接、`![[图.png]]` 形式的附件，处理方式与同类情况对齐。

## 已知边界

- **下线只是从当前版本移除**：站点仓库是公开的 git 仓库，曾经公开过的内容在历史提交里仍可检索。彻底抹掉需要重写历史并强推。把目录加进 `kb_public` 前要确认里面每一篇都可公开。
- **`个人项目/博客` 有 4 篇因示例邮箱 `admin@blog.com` 被拦**（项目概览、API 文档、使用手册、故障排除）。这是敏感检查按规矩办事；要公开就把示例邮箱改成 `admin@example.com` 之类，改完下次同步会自动上站。
- **图片和附件一律不上传**，页面上显示「（图片未公开）」。
